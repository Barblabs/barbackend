# Each Customer connects its own Slack workspace; every Finding reaches its owner as a DM and the Security Team channel in full

Each Customer installs barbattack's Slack app into its own workspace from the portal's Connect Slack button: OAuth runs in a popup, one installation per Customer, and the bot token is stored encrypted like CMDB credentials (ADR 0012). We use a bot token rather than incoming webhooks because alerts must reach individual Asset Owners by email and a Customer-wide channel; a webhook is bound to one channel and has no identity. The scopes are `chat:write`, `users:read`, `users:read.email`, `chat:write.public`, `channels:read` and `groups:read`. `users:read.email` resolves Asset Owner emails to Slack users, which a workspace admin may question at consent, but the alternative is asking every owner to link an account by hand; `users:read` rides along because Slack rejects the consent screen with `invalid_scope` when the email scope is requested without it. `channels:read` and `groups:read` let the portal list the workspace's public channels and the private channels the app has been added to, so the admin picks the Security Team channel from a list instead of pasting an id; a private channel only appears once someone adds the app to it, because Slack shows an app no private channel it is not in. An installation is `active`, `needs re-authorisation` or `removed`; Slack's `invalid_auth` or `token_revoked` on a send flips it to `needs re-authorisation`, so a revoked app never fails silently.

Every Finding the pipeline emits is DM'd to the Asset Owner of its Asset, and the identical message is posted to the Security Team channel. One Finding produces one DM and one channel post; a hundred Findings produce a hundred of each. The channel is not a summary: the Security Team uses it for visibility and as evidence of what was reported, so it mirrors the DMs one for one. Both copies name the Asset Owner's email. A Finding with no owner, or whose owner Slack does not know, still reaches the channel; the DM row fails as `owner_unreachable` so an admin can see it (ADR 0026). The Slack layer decides nothing about when alerts are produced and keeps no dedupe; the pipeline writes the messages and a worker sends them every minute (ADR 0026). An alert carries the CVE ID, the Asset and a portal link, the Asset Owner's email, the Score and Score Band, why it matters (KEV, EPSS, CVSS, Criticality, Exposure) and the agent's recommendation; the Slack layer never reads Feeds or Scores itself, the pipeline hands it the alert's fields.

Alerts fire for every Finding the agent emits, not only on a Score Band change or KEV entry: the pipeline has already filtered, enriched, scored and re-prioritised, so anything that reaches delivery is worth a message. This supersedes the alerting rule in ADR 0009.
